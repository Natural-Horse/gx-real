# gx-real 实机测试指南

本文给出 `Go2 + X5 + 远程 StarVLA` 的完整测评链路。模型服务运行在 GPU 服务器并仅监听 `127.0.0.1`；工作站建立 SSH 双跳隧道；Jetson 采集 front/wrist JPEG、调用模型，并将 NAV 与机械臂目标送入 gx-real 的受限 ROS 接口。

## 1. 链路与安全边界

```text
GPU 服务器 StarVLA
  -> route + subtask + NAV waypoint / base-frame TCP
  -> SSH 回环隧道
Jetson scripts/vla_real_client.py
  -> /vla/base_cmd -> WBC watchdog/状态门/加速度限幅 -> Go2 腿部 policy
  -> /vla/arm_target -> workspace/单步/watchdog -> X5 Cartesian controller -> CAN
  -> JSONL 决策与执行提案日志
```

- 远程客户端不直接打开 CAN，也不替换 `policies/policy.onnx`。该 ONNX 仍是 Go2 的 12 关节底层运控。
- X5 仍只有一个 CAN owner。`run_vla_arm_real.sh` 启动的独立节点持有 CAN，WBC 只读取 `/arm/state` 和 `/arm/target_state`。
- `shadow` 是默认模式，只做在线图像推理和安全适配，不发布动作。
- `live` 必须同时给出两个显式确认参数；网络、图像、推理、底盘命令或机械臂命令过期都会零速/保持。
- 当前已通过纯 Python 和静态 ROS 边界测试，尚未完成真实相机、Go2 和 X5 的动态联合验收。第一次上机必须按第 8 节逐级放行。

## 2. 必要前检

只保留会阻止安全启动的检查：

1. 操作者握住手柄与急停，清空 Go2 和 X5 工作区。
2. `eth0`、`can0`、X5 24V 和机械臂反馈正常；X5 不得存在第二个 CAN owner。
3. front/wrist 必须发布 `sensor_msgs/CompressedImage`，内容必须是 JPEG。
4. `/arm/state` 和 `/arm/target_state` 必须 valid、fresh，初始臂姿态为 `[0, 0.3, 0.5, 0, 0, 0]`。

不可省略的底层基线：flat policy 的 12 个腿关节使用 `Kp=40, Kd=1`；Go2 人工基线入口是 `scripts/run_fixed_03_real.sh`；正常收尾使用 `/arm/home`，硬故障使用 `/safety/estop`；当前 X5 完全打开标定读数为 `-5.07839`，硬件或 SDK 变化后必须重新校准。

## 4. 启动服务器

每次先由用户确认 `zju-server` 或 `robotdiff_new`，并检查 GPU 进程归属。服务必须用独立 tmux 且只监听回环：

```bash
cd /path/to/starVLA_sc
CHECKPOINT=/absolute/path/to/final_model/pytorch_model.pt \
GPU=<空闲卡> PORT=10093 TMUX_SESSION=go2_vla_real_eval \
scripts/evaluation/start_go2_vla_server_tmux.sh

tmux capture-pane -pt go2_vla_real_eval:server -S -120
ss -lntp | grep 10093
```

`ss` 必须显示 `127.0.0.1:10093`，不能是 `0.0.0.0`。checkpoint metadata、动作维度与 `starvla-go2-eval/v2` 必须一致。

## 5. 建立 SSH 双跳

在同时能连接服务器和 `robodog` 的工作站运行：

```bash
cd /home/natural/Desktop/mtr/gx-real
REMOTE_PORT=10093 LOCAL_RELAY_PORT=10094 ROBOT_PORT=10093 \
  scripts/evaluation/manage_remote_vla_tunnel.sh start zju-server robodog

scripts/evaluation/manage_remote_vla_tunnel.sh check zju-server robodog
```

最终链路是 `robodog 127.0.0.1:10093 -> 工作站 -> 服务器 127.0.0.1:10093`。切换到 `robotdiff_new` 时只替换服务器 alias。

robodog 当前没有默认路由且系统时间未同步。单独换 DNS 不能恢复 GitHub；即便改为 `1.1.1.1` 或 `223.5.5.5`，也必须先有正确默认网关并同步时间。代码同步继续使用工作站 Git bundle、scp 或 rsync over SSH。

## 6. Shadow 验证

先验证隧道与协议，不 source ROS：

```bash
cd ~/gx-real
/usr/bin/python3 scripts/vla_shadow_client.py \
  --endpoint ws://127.0.0.1:10093 \
  --health-only
```

然后 source 环境，确认两个相机 topic，再启动在线 shadow：

```bash
cd ~/gx-real
source scripts/setup_env.sh
ros2 topic info /camera/front/image_raw/compressed
ros2 topic info /camera/wrist/image_raw/compressed

scripts/run_vla_real_client.sh \
  --mode shadow \
  --endpoint ws://127.0.0.1:10093 \
  --episode-id real_shadow_0001 \
  --instruction "<本条任务的完整全局 instruction>" \
  --jsonl-out logs/vla_eval/real_shadow_0001.jsonl
```

验收：连续记录 route/subtask、NAV proposal 或 arm gate；`published=false`；没有 `/vla/base_cmd` 和 `/vla/arm_target` 的动作发布。

## 7. Live 启动顺序

以下步骤只有完成 shadow 审核后才能执行，每个命令独立终端运行。

终端 A，X5 唯一 CAN owner：

```bash
cd ~/gx-real
scripts/run_vla_arm_real.sh
```

终端 B，Go2 WBC 与外部速度源：

```bash
cd ~/gx-real
scripts/run_vla_leg12_real.sh
```

仍按底层流程用 `R1` 起身、确认臂状态后用 `L2` 进入 policy。WBC 在收到新 VLA 速度前保持零速。

终端 C，显式放行动作输出：

```bash
cd ~/gx-real
scripts/run_vla_real_client.sh \
  --mode live \
  --enable-live-output \
  --confirm-live-output I_UNDERSTAND_LIVE_OUTPUT \
  --endpoint ws://127.0.0.1:10093 \
  --episode-id real_live_0001 \
  --instruction "<本条任务的完整全局 instruction>" \
  --jsonl-out logs/vla_eval/real_live_0001.jsonl
```

NAV 使用模型第一个机体系 waypoint 生成限幅速度；GRASP/PLACE 每次只消费当前 chunk 的第一个 base-frame TCP target，下一个推理周期重新闭环。模型夹爪 `0..1` 映射到 X5 `0..0.088 m`。所有 TCP 在客户端和 X5 owner 节点各检查一次。

## 8. 分级放行

1. held-out route/subtask/action 离线指标。
2. mock WebSocket 与 health/reset/infer 静态测试。
3. 真实 checkpoint + 保存 JPEG 的离线 shadow。
4. 在线双相机 shadow，人工控制机器人。
5. `run_vla_arm_real.sh --dry-run --allow-missing-can` 与外部 TCP topic dry-run。
6. Go2 吊架或安全支撑，确认 `/vla/base_cmd` 过期后 0.25 s 内归零。
7. X5 单步小位移，确认 workspace、0.08 m 客户端限幅和 0.15 m owner 限幅。
8. 空场低速 NAV，再分别验证 GRASP、PLACE。
9. 最后执行完整任务并统计 episode 成功率、超时率和安全拒绝率。

当前代码完成到可执行第 5 级的静态实现；第 6--9 级必须现场动态验收后才能标记通过。

## 9. 停止与故障

正常停止顺序：先 `Ctrl+C` 停终端 C；对 WBC 按 `L1`，等待零速、趴下和 `/arm/home` 完成；再退出终端 A；最后在工作站关闭隧道：

```bash
scripts/evaluation/manage_remote_vla_tunnel.sh stop zju-server robodog
```

- 协议或 request ID 不一致：拒绝响应，不能沿用旧动作。
- 推理或图像过期：底盘零速，X5 保持当前位姿。
- arm workspace/step rejected：检查坐标系和 checkpoint，禁止调大阈值绕过。
- CAN owner 冲突：停止重复的机械臂节点，只保留 `run_vla_arm_real.sh`。
- `recover` 或模型异常 route：当前只零速记录，不自动执行恢复动作。
