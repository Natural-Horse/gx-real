# gx-real 实机测试指南（Go2 + X5 + 远程 StarVLA 完整部署）

本文覆盖从**开机前自检、启动准备、各节点启动、拿到服务器推理结果，到最终执行动作**的
全过程。链路为：GPU 服务器跑 StarVLA 推理 → 工作站建 SSH 双跳隧道 → robodog 上
RealSense 相机采集 front/wrist JPEG → 交互 client 调用模型 → NAV 速度给 Go2 WBC、
GRASP/PLACE 目标给 X5 CAN owner。

## 1. 链路与安全边界

```text
GPU 服务器（starVLA_sc 推理服务，仅监听 127.0.0.1）
  -> route + subtask + NAV waypoint / base-frame TCP
  -> SSH 双跳隧道（robodog 10093 -> 工作站 10094 -> 服务器 10093）
robodog 交互 client（run_vla_real_interactive.py）
  -> /vla/base_cmd -> Go2 WBC（限幅/看门狗/状态门）-> 腿部 policy
  -> /vla/arm_target -> X5 owner（workspace/单步/watchdog）-> Cartesian 控制 -> CAN
  -> JSONL 决策与执行记录
```

- 远程 client 不打开 CAN，不替换 `policies/policy.onnx`；X5 只有一个 CAN owner
  （`run_vla_arm_real.sh`），WBC 只读 `/arm/state`、`/arm/target_state`。
- `shadow` 是默认模式：在线推理 + 安全适配，不发布动作；`live` 必须显式双确认。
- 网络/图像/推理/命令过期一律零速或保持，不沿用旧动作。
- 当前状态：真实相机 + 隧道 + 服务器推理闭环已验证（shadow）；第 6~9 级动态验收待现场。

## 2. 开机前自检（上电前）

1. Go2 与 X5 周围清空，操作者握住手柄并确认硬件急停可用、L1 可触发。
2. X5 24V 供电正常，CAN H/L 与终端电阻确认，USB-CAN 使用
   `/dev/serial/by-id/usb-Openlight_Labs_CANable2*`（不要硬编码 `/dev/ttyACM*`）。
3. 两台 RealSense 相机接好（腕部 D436、前置相机），USB 口接触良好。
4. Go2 吊起或安全趴卧（MCF 释放会撤掉内置运动控制器）。

## 3. 启动准备（上电后、起节点前，robodog 上）

```bash
cd ~/gx-real
conda deactivate
source scripts/setup_env.sh

CAN_DEV=$(ls /dev/serial/by-id/usb-Openlight_Labs_CANable2* 2>/dev/null | head -1)
scripts/prepare_real_run.sh --network-iface eth0 --can-dev "$CAN_DEV" --can-if can0 --no-spacemouse
```

一键前置会完成构建、环境检查、can0 配置、Go2 topic 检查与 MCF 释放；
VLA 链路不用 SpaceMouse，用 `--no-spacemouse` 跳过其检查。必须看到：
`can0` 为 `UP,LOWER_UP`、`MCF release verified`、无重复的 WBC/X5 写进程。

### 3.1 单独验证 X5 能读到关节

```bash
cd ~/gx-real
source scripts/setup_env.sh
cd arx5-sdk
/usr/bin/python3 python/examples/calibrate.py X5 can0
```

正常会持续打印 6 个关节角，**移动机械臂后数值必须变化**。如果一直全零或
`missing feedback`，不要继续启动：检查 X5 24V、急停、CAN H/L、终端电阻、
USB-CAN 设备号、是否有其他进程占用 can0（`pgrep -af "run_spacemouse_arm|calibrate.py|arx5|candump"`）。

夹爪标定：本机闭合零位掉电易失，已用软件零位偏移解决（见
`real-wbc/modules/arx5_gripper_calib.py`：`X5_GRIPPER_ZERO_OFFSET=-6.348`、
`X5_GRIPPER_OPEN_READOUT=5.0784`），节点启动自动应用，日常无需交互式标定。
换臂/换电机后重测：`bash scripts/calibrate_gripper.sh`（闭合按回车 -> 全开按
回车），把实测值更新回该文件。

### 3.2 验证相机

```bash
cd ~/gx-real && source scripts/setup_env.sh
v4l2-ctl --list-devices
timeout 8 ros2 topic list | grep camera
```

`v4l2-ctl --list-devices` 应看到两台 RealSense；起发布器后 topic 列表应有
front/wrist 两个。

## 5. robodog 节点启动

一键启动（四个独立 tmux 会话）：

```bash
cd ~/gx-real
bash scripts/run_vla_real_all.sh --config configs/vla_eval/real_go2_x5.yaml start
bash scripts/run_vla_real_all.sh --config configs/vla_eval/real_go2_x5.yaml check
```

也可用**单个 tmux 会话 2x2 四宫格**同时显示四个节点（适合现场盯日志）：

```bash
bash scripts/run_vla_real_quad.sh --config configs/vla_eval/real_go2_x5.yaml start
tmux attach -t go2_vla_quad
bash scripts/run_vla_real_quad.sh --config configs/vla_eval/real_go2_x5.yaml stop
```

布局：左上 `vla_cams`、右上 `vla_leg`、左下 `vla_arm`、右下 `vla_client`；
`tmux attach` 后用 Ctrl-B + 方向键切 pane，GRASP/PLACE 在 client pane 输 1/0。
两套启动方式二选一，不要同时用。

启动的会话：

| tmux 会话 | 节点 | 作用 |
|---|---|---|
| `vla_cams` | `publish_real_cameras.py` | RealSense RGB -> JPEG topic（front/wrist） |
| `vla_leg` | `run_vla_leg12_real.sh` | Go2 WBC，消费 `/vla/base_cmd` 速度 |
| `vla_arm` | `run_vla_arm_real.sh` | X5 唯一 CAN owner，消费 `/vla/arm_target` |
| `vla_client` | `run_vla_real_interactive.py` | 订阅相机、调服务器、按 route 分发 |

需要单独调试时逐条启动（每条一个终端/tmux）：

```bash
cd ~/gx-real && source scripts/setup_env.sh
python3 scripts/publish_real_cameras.py
bash scripts/run_vla_leg12_real.sh
bash scripts/run_vla_arm_real.sh
python3 scripts/run_vla_real_interactive.py --config configs/vla_eval/real_go2_x5.yaml
```

依次对应：相机、WBC（R1 起身、L2 进 policy）、X5 机械臂、交互 client。

## 6. Shadow 验证：拿到服务器推理结果（不执行）

默认配置即 shadow。client 启动后会打印 `server health`，随后逐帧输出
`route/subtask/waypoints/arm_targets` 并写入
`logs/vla_eval/real_vla_interactive.jsonl`。NAV 会发布 `/vla/base_cmd`（无 WBC 时不移动），
GRASP/PLACE 只记录不发布。

验收：

```bash
tail -f ~/gx-real/logs/vla_client.log
tail -f ~/gx-real/logs/vla_eval/real_vla_interactive.jsonl
timeout 8 ros2 topic info /camera/front/image_raw/compressed
```

查看图像：

**推荐：一键打开 rviz2 直接看两路相机**（自动起相机+解压节点，独立于四宫格）：

```bash
cd ~/gx-real
bash scripts/view_cameras_rviz.sh
```

脚本会确保 `publish_real_cameras.py`（vla_cams）与 `decompress_cameras.py`
（vla_decompress，JPEG -> 原始 Image）在跑，然后打开 rviz2 并显示
`/camera/front/image_raw` 与 `/camera/wrist/image_raw` 两个面板；需要图形会话
（桌面终端或 ssh -X）。

**备选：topic 里存一帧 JPEG（无 GUI 时）**：

```bash
cat > /tmp/snap.py <<'EOF'
import rclpy
from rclpy.node import Node
from sensor_msgs.msg import CompressedImage
class S(Node):
    def __init__(self):
        super().__init__("snap")
        self.create_subscription(CompressedImage, "/camera/front/image_raw/compressed", lambda m: open("/tmp/front.jpg","wb").write(bytes(m.data)) or print("front", len(m.data)), 5)
        self.create_subscription(CompressedImage, "/camera/wrist/image_raw/compressed", lambda m: open("/tmp/wrist.jpg","wb").write(bytes(m.data)) or print("wrist", len(m.data)), 5)
rclpy.init(); n = S()
import time
for _ in range(50): rclpy.spin_once(n, timeout_sec=0.2)
rclpy.shutdown()
EOF
source scripts/setup_env.sh && python3 /tmp/snap.py
```

## 7. Live 执行（通过分级放行后）

先按第 8 节完成分级验收，再执行：

终端 A（X5）：`bash scripts/run_vla_arm_real.sh`
终端 B（WBC）：`bash scripts/run_vla_leg12_real.sh`；按 R1 起身、确认 `/arm/state`
有效后用 L2 进入 policy（收到 VLA 速度前保持零速）。
终端 C（client 显式放行）：

```bash
cd ~/gx-real && source scripts/setup_env.sh
python3 scripts/run_vla_real_interactive.py --config configs/vla_eval/real_go2_x5.yaml \
  --override real.mode=live \
  --override real.enable_live_output=true \
  --override real.confirm_live_output=I_UNDERSTAND_LIVE_OUTPUT
```

- NAV：执行模型第一个机体系 waypoint 生成限幅速度，到位后重规划；
- GRASP/PLACE：终端阻塞，输入 `1` 执行 / `0` 跳过，期间不发起新推理；
- 夹爪 `0..1` 映射 X5 `0..0.088 m`；TCP 在 client 和 X5 owner 各校验一次
  （workspace、0.08 m client 限幅、0.15 m owner 限幅）。

## 8. 分级放行

1. held-out route/subtask/action 离线指标；
2. mock WebSocket health/reset/infer 静态测试；
3. 真实 checkpoint + 保存 JPEG 的离线 shadow；
4. 在线双相机 shadow（人工控制机器人，不执行）；
5. `run_vla_arm_real.sh --dry-run --allow-missing-can` 与外部 TCP topic dry-run；
6. Go2 吊架/安全支撑，确认 `/vla/base_cmd` 过期后 0.25 s 内归零；
7. X5 单步小位移，确认 workspace 与两级限幅；
8. 空场低速 NAV，再分别验证 GRASP、PLACE；
9. 完整任务，统计成功率、超时率、安全拒绝率。

当前完成到第 5 级静态实现 + 第 4 级在线双相机 shadow 实测；第 6~9 级必须现场动态验收。

## 9. 停止与故障

正常停止：先停 client（Ctrl+C 或 `run_vla_real_all.sh stop`）→ WBC 按 L1 等零速/趴下/
`/arm/home` 完成 → 停臂 → 工作站关隧道：

```bash
scripts/evaluation/manage_remote_vla_tunnel.sh stop zju-server robodog
```

常见故障：

- `/arm/state` 无数据/不更新：先查 X5 24V、CAN、`calibrate.py` 能否读到关节变化
  （历史原因多为线没插好/CAN owner 冲突）。
- `can0` 不存在：`setup_arx_can.sh` 重新配置，用 by-id 路径。
- `MCF release verified` 失败：确认狗吊起/趴卧、网段 192.168.123.x、无其他 Unitree 进程。
- arm workspace/step rejected：检查坐标系与 checkpoint，禁止调大阈值绕过。
- 推理/图像过期：底盘零速、X5 保持，不沿用旧动作。
- `recover`/异常 route：当前只零速记录，不自动执行恢复。
