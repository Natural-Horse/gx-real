# gx-real 实机测试指南（Go2 + X5 + 远程 StarVLA 完整部署）

本文覆盖从**开机前自检、启动准备、各节点启动、拿到服务器推理结果，到最终执行
动作**的完整流程，并给出交互确认、紧急停止与当前安全边界。链路为：GPU 服务器跑
StarVLA 推理 → 工作站建 SSH 双跳隧道 → robodog 上 RealSense 采集 front/wrist
JPEG → 交互 client 调模型 → NAV 速度给 Go2 WBC、GRASP/PLACE 目标给 X5 CAN owner。

## 1. 统一配置文件（所有参数按模块组织）

所有节点参数都在**同一个 yaml** 中按模块组织，启动器与 client 都从这里读取：

```text
configs/vla_eval/real_go2_x5.yaml
  server:      推理服务 endpoint / 超时
  task:        instruction / episode_id
  camera:      相机设备、topic、帧率、JPEG 质量
  leg:         Go2 WBC（standup、external_vla 速度源、/arm/state 等 topic）
  arm:         X5（model、can、external_vla 目标源、estop topic）
  client:      mode（shadow/live）、双确认、nav 锚定、图像/命令 topic
  interactive: confirm_nav / confirm_arm、确认提示、nav 步进等
```

启动器 `scripts/run_vla_real_quad.sh`（四宫格）和 `scripts/run_vla_real_all.sh`
（独立会话）都会调用 `scripts/vla_config_args.py` 按模块生成 camera/leg/arm 的
启动参数；client 自己读 yaml。临时改参数用 `--override 模块.键=值`，例如：

```bash
bash scripts/run_vla_real_quad.sh --config configs/vla_eval/real_go2_x5.yaml \
  --override client.mode=live --override client.enable_live_output=true \
  --override client.confirm_live_output=I_UNDERSTAND_LIVE_OUTPUT \
  --override interactive.confirm_arm=false start
```

交互确认开关：

- `interactive.confirm_nav`（默认 true）：首次推理 / route 变化 / 上一动作被拒时，
  nav 动作在 client 终端阻塞询问；
- `interactive.confirm_arm`（默认 true）：同上，但作用于 grasp/place 机械臂动作。
  置为 false 表示机械臂动作不阻塞、直接执行（仍受 workspace/单步安全门控）。

## 2. 链路与安全边界

```text
GPU 服务器（starVLA_sc 推理服务，仅监听 127.0.0.1）
  -> route + subtask + NAV waypoint / base-frame TCP
  -> SSH 双跳隧道（robodog 10093 -> 工作站 10094 -> 服务器 10093）
robodog 交互 client（run_vla_real_interactive.py）
  -> /vla/base_cmd -> Go2 WBC（限幅/看门狗/状态门）-> 腿部 policy
  -> /vla/arm_target -> X5 owner（workspace/单步/watchdog）-> Cartesian 控制 -> CAN
  -> JSONL 决策与执行记录
```

- 远程 client 不打开 CAN，不替换 `policies/policy.onnx`；X5 只有一个 CAN owner
  （`run_vla_arm_real.sh`），WBC 只读 `/arm/state`、`/arm/target_state`。
- `shadow` 是默认模式：在线推理 + 安全适配，**不发布任何动作**
  （代码强制：NAV/GRASP/PLACE 都不发 `/vla/base_cmd` 或 `/vla/arm_target`）。
- `live` 必须三条件齐备才放行：`client.mode=live`、
  `client.enable_live_output=true`、`client.confirm_live_output=I_UNDERSTAND_LIVE_OUTPUT`。
- 网络/图像/推理/命令过期一律零速或保持，不沿用旧动作。
- 当前状态：真实相机 + 隧道 + 服务器推理闭环已验证（shadow）；实机动态执行
  仍需按第 11 节分级放行，机械臂部分当前**不建议无监督执行**（见第 9 节）。

## 3. 开机前自检（上电前）

1. Go2 与 X5 周围清空，操作者握住手柄并确认硬件急停可用、L1 可触发。
2. X5 24V 供电正常，CAN H/L 与终端电阻确认，USB-CAN 使用
   `/dev/serial/by-id/usb-Openlight_Labs_CANable2*`（不要硬编码 `/dev/ttyACM*`）。
3. 两台 RealSense 相机接好（腕部 D436、前置相机），USB 口接触良好。
4. Go2 吊起或**安全趴卧**（MCF 释放会撤掉内置运动控制器；不要提前起身）。

## 4. 启动准备（上电后、起节点前，robodog 上）

```bash
cd ~/gx-real
conda deactivate
source scripts/setup_env.sh

CAN_DEV=$(ls /dev/serial/by-id/usb-Openlight_Labs_CANable2* 2>/dev/null | head -1)
scripts/prepare_real_run.sh --network-iface eth0 --can-dev "$CAN_DEV" --can-if can0 --no-spacemouse
```

一键前置会完成构建、环境检查、can0 配置、Go2 topic 检查与 MCF 释放；必须看到
`can0 UP,LOWER_UP` 和 `MCF release verified`，且无重复的 WBC/X5 写进程。

### 4.1 单独验证 X5 能读到关节

```bash
cd ~/gx-real
source scripts/setup_env.sh
cd arx5-sdk
/usr/bin/python3 python/examples/calibrate.py X5 can0
```

正常会持续打印 6 个关节角，**移动机械臂后数值必须变化**。如果一直全零或
`missing feedback`，不要继续启动：检查 X5 24V、急停、CAN H/L、终端电阻、
USB-CAN 设备号、是否有其他进程占用 can0（`pgrep -af "run_spacemouse_arm|calibrate.py|arx5|candump"`）。

夹爪标定：本机闭合零位掉电易失，已用软件零位偏移解决
（`real-wbc/modules/arx5_gripper_calib.py`：
`X5_GRIPPER_ZERO_OFFSET=-6.348`、`X5_GRIPPER_OPEN_READOUT=5.0784`），
节点启动自动应用，日常无需交互式标定。换臂/换电机后重测：
`bash scripts/calibrate_gripper.sh`（闭合按回车 -> 全开按回车），
把实测值更新回该文件。

### 4.2 验证相机

```bash
cd ~/gx-real && source scripts/setup_env.sh
v4l2-ctl --list-devices
timeout 8 ros2 topic list | grep camera
```

`v4l2-ctl --list-devices` 应看到两台 RealSense；起发布器后 topic 列表应有
front/wrist 两个。

## 6. robodog 节点启动

推荐**单 tmux 会话 2x2 四宫格**（适合现场盯日志）：

```bash
cd ~/gx-real
bash scripts/run_vla_real_quad.sh --config configs/vla_eval/real_go2_x5.yaml start
tmux attach -t go2_vla_quad
```

布局：左上 `cams`（相机）、右上 `leg`（WBC）、左下 `arm`（X5）、
右下 `client`（交互终端）。`tmux attach` 后用 Ctrl-B + 方向键切 pane；
**需要确认动作时切到右下 client pane 输入 0（否）或 1（是）**。

也可用四个独立 tmux 会话：

```bash
bash scripts/run_vla_real_all.sh --config configs/vla_eval/real_go2_x5.yaml start
bash scripts/run_vla_real_all.sh --config configs/vla_eval/real_go2_x5.yaml check
```

两套方式二选一，不要同时用。日志分别在
`logs/vla_{cams,leg,arm,client}.log`。

## 7. 完整启动顺序（严格流程）

机器狗保持**趴卧**、机械臂 0 位即可，不要提前起身。按序执行：

1. 第 4 节前置：`prepare_real_run.sh`（趴卧时做，MCF 释放）+ X5 关节验证 +
   相机验证。
2. 第 5 节：确认服务器 10093 在监听、双跳隧道两端 `check` 通过。
3. 第 6 节启动四个节点。等 arm pane 发布 `/arm/state`
   （`ros2 topic echo /arm/state --once` 能读到夹爪约 0.088、关节非零）；
   WBC 带 `--require-arm-state-for-rl`，没有 `/arm/state` 不会放行 policy。
4. **起身与进 policy**（手柄/WBC pane）：按 R1 内部起身 → 站稳后按 L2 进入
   policy（初始零速）→ 观察 3 秒，确认腿部无异常抖动。此时 client 可能已阻塞在
   第一次推理的确认上，先不要输 1。
5. 交互执行：确认狗站稳、policy 正常后，切到右下 client pane，逐个看打印的
   预测动作再输 1/0（规则见第 8 节）。

中途任何异常：先按 L1（见第 10 节），再看日志。

## 8. 交互确认规则（client 终端）

client 终端（右下 pane / `vla_client` 会话）在以下情况**阻塞**并打印下一个预测
动作（nav 显示第一个 waypoint，grasp/place 显示 base 系 TCP 目标），询问
`0=否 1=是`，期间不发新推理、不执行动作：

- 本次运行的**第一次推理结果**；
- 得到的 **route 与上一次不同**（如 nav -> grasp、grasp -> place）；
- **上一动作被你拒绝执行**（输入 0）或安全门拒绝之后的下一次推理。

同 route 的连续执行（如连续 nav waypoint 重规划）不重复询问。
`interactive.confirm_nav` / `interactive.confirm_arm` 置 false 可分别关闭
nav / 机械臂的阻塞确认（机械臂仍受 workspace/单步门控）。

live 启动（client 放行动作）：

```bash
cd ~/gx-real && source scripts/setup_env.sh
python3 scripts/run_vla_real_interactive.py --config configs/vla_eval/real_go2_x5.yaml \
  --override client.mode=live --override client.enable_live_output=true \
  --override client.confirm_live_output=I_UNDERSTAND_LIVE_OUTPUT
```

- NAV：执行模型第一个机体系 waypoint 生成限幅速度，到位后重规划；
- GRASP/PLACE：按第 8 节规则在 client 终端阻塞确认后发布；
- 夹爪 `0..1` 映射 X5 `0..0.088 m`；TCP 在 client 和 X5 owner 各校验一次
  （workspace、0.08 m client 限幅、0.15 m owner 限幅）。

shadow 验证（默认，不执行）：client 打印 `server health` 后逐帧输出
`route/subtask/waypoints/arm_targets` 并写入
`logs/vla_eval/real_vla_interactive.jsonl`；**不发布任何动作**。

## 9. 当前安全边界与可靠性（如实说明）

- NAV：速度被限制在 vx≤0.20、vy≤0.10 m/s、yaw≤0.30 rad/s，命令 0.25 s 无更新
  自动归零；waypoint 落在训练数据范围内的比例约 82%，低速有人盯可以试。
  `client.nav_anchor_mode`：`body`（无里程计，执行约 1 s 限幅速度后重规划）；
  若现场有 `/odom`，改 `odom` 为"走到第一个 waypoint 后再推理"。
- 机械臂：**当前不能保证推理质量**。最新大样本：TCP 位置中位误差约 0.17 m、
  姿态误差中位约 2.6 rad（基本不可用）、夹爪输出趋中；一段完整的 grasp/pick
  仍欠拟合。workspace/单步门控只能挡"越界"，挡不住"语义错"。因此机械臂动作
  必须逐个看 TCP 目标再确认，手放在手柄 L1 上；本轮建议先 shadow 验收。
- 所有关键向量有 finite 检查；推理/图像/命令过期一律零速或保持。

## 10. 紧急停止（一键让狗和臂都停）

- **手柄 L1**：第一次按 = 受控停机（底盘速度斜坡归零 -> 趴卧 -> 发布
  `/arm/home` 让 X5 回 home -> 切 damping）；停机过程中**再按 L1** = 立即急停
  （WBC 连发 `/safety/estop=True`，X5 节点收到后立刻切 damping 原地停）。
- **硬件急停按钮**：任何时候优先。
- 终端 Ctrl+C：X5 节点退出时会先尝试回 home 再切 damping；WBC 进程退出后停止
  下发低层指令。应急顺序永远是先 L1，再去动终端。

正常停止顺序：先 L1 受控停机 -> Ctrl+C client ->
`bash scripts/run_vla_real_quad.sh --config configs/vla_eval/real_go2_x5.yaml stop`
-> 工作站关隧道：

```bash
scripts/evaluation/manage_remote_vla_tunnel.sh stop zju-server robodog
```

## 11. 分级放行

1. held-out route/subtask/action 离线指标；
2. mock WebSocket health/reset/infer 静态测试；
3. 真实 checkpoint + 保存 JPEG 的离线 shadow；
4. 在线双相机 shadow（人工控制机器人，不执行）；
5. `run_vla_arm_real.sh --dry-run --allow-missing-can` 与外部 TCP topic dry-run；
6. Go2 吊架/安全支撑，确认 `/vla/base_cmd` 过期后 0.25 s 内归零；
7. X5 单步小位移，确认 workspace 与两级限幅；
8. 空场低速 NAV，再分别验证 GRASP、PLACE；
9. 完整任务，统计成功率、超时率、安全拒绝率。

当前完成到第 5 级静态实现 + 第 4 级在线双相机 shadow 实测；第 6~9 级必须
现场动态验收。

## 12. 停止与故障排查

常见故障：

- `/arm/state` 无数据/不更新：先查 X5 24V、CAN、`calibrate.py` 能否读到关节
  变化（历史原因多为线没插好/CAN owner 冲突）。
- `can0` 不存在：`setup_arx_can.sh` 重新配置，用 by-id 路径。
- `MCF release verified` 失败：确认狗吊起/趴卧、网段 192.168.123.x、
  无其他 Unitree 进程。
- arm workspace/step rejected：检查坐标系与 checkpoint，禁止调大阈值绕过。
- 推理/图像过期：底盘零速、X5 保持，不沿用旧动作。
- `recover`/异常 route：当前只零速记录，不自动执行恢复。

查看图像：`bash scripts/view_cameras_rviz.sh`（自动起相机+解压节点并打开 rviz2
显示两路相机，需图形会话或 ssh -X）。
